# CABT Online Battle Arena · AI / Player Matchmaking / Replay Viewer

Windows에서 Kaggle 제출형 CABT AI와 대전하거나, 공개 서버에서 다른 플레이어와 온라인 1대1 대전을 하고, 저장된 CABT 리플레이를 다시 확인할 수 있는 GUI입니다.

이 배포본은 Windows 데스크톱 브라우저 UI를 기준으로 구성되어 있습니다.

## 실행

1. ZIP을 원하는 폴더에 **전체 압축 해제**합니다.
2. `RUN_CABT.bat`을 더블 클릭합니다.
3. 브라우저가 자동으로 열리면 대전 또는 리플레이 보기를 선택합니다.

별도의 Python 설치나 명령어 입력은 필요 없습니다. 첫 실행에서만 공식 휴대용 Python 런타임과 NumPy를 이 폴더 안에 자동으로 준비하므로 인터넷 연결이 필요하며, 이후에는 같은 PC에서 오프라인 실행할 수 있습니다.

브라우저가 자동으로 열리지 않으면 `http://127.0.0.1:8765`를 직접 여세요. 서버 종료는 실행 창에서 `Ctrl+C`입니다.

## 리플레이 불러오기

대기실 상단의 **리플레이 불러오기** 버튼 또는 리플레이 드롭 영역을 사용합니다. 파일을 끌어다 놓는 방식도 지원합니다.

지원 형식:

- CABT 기록 ZIP: `metadata.json`, `replay_visualize.json`, `transitions.jsonl`이 들어 있는 기록 파일
- 공식 에피소드 JSON: Kaggle에서 내려받는 `configuration / info / steps / rewards / statuses` 구조
- `replay_visualize.json`: 보드 장면을 순서대로 재생
- `transitions.jsonl`: 관측값과 선택 액션을 함께 재생

CABT가 직접 생성한 기록 ZIP을 불러오면 가장 많은 정보를 복원합니다. ZIP 내부 파일이 한 단계 이상의 폴더 안에 있어도 자동으로 찾습니다.

### 재생 조작

- `◀` / `▶`: 이전·다음 프레임
- `Ⅱ` / `▶`: 자동 재생 일시정지·재개
- 재생 속도: `0.5×`~`4×`
- 타임라인 슬라이더: 원하는 장면으로 즉시 이동
- 관전 시점: Player 0 / Player 1 전환
- 오른쪽 액션 기록: 해당 항목을 클릭해 그 장면으로 이동
- 키보드: `←`, `→`, `Home`, `End`, `Space`

`transitions.jsonl`이 포함된 기록에서는 해당 장면에서 실제로 선택된 옵션을 강조해서 표시합니다. JSON 장면 파일만 불러온 경우에는 선택 액션 없이 보드 장면 중심으로 재생합니다.

리플레이를 닫으면 기존 대기실로 돌아가 새 게임을 시작할 수 있습니다.

## 새 AI 추가

대기실의 **Kaggle 제출 ZIP 추가**를 누르고 제출 파일을 그대로 선택합니다. ZIP 루트 또는 한 단계 아래에서 다음 구조를 자동으로 찾습니다.

```text
submission.zip
├─ main.py
├─ deck.csv
└─ cg/
   ├─ api.py
   ├─ game.py
   └─ cg.dll
```

`main.py`에는 아래 Kaggle 진입점이 있어야 합니다.

```python
def agent(observation: dict) -> list[int]:
    ...
```

초기 호출에서는 60장 덱을, 게임 중에는 현재 선택지의 option index 배열을 반환해야 합니다. 중첩 폴더가 있는 제출 ZIP도 `main.py`와 `deck.csv`가 같은 폴더에 있으면 인식합니다.

신뢰할 수 있는 본인 AI만 추가하세요. 제출 Python 코드는 로컬 PC에서 실행됩니다.

## AI 액션 재생

- AI는 한 번의 요청에서 **정확히 한 액션만** 실행합니다.
- `Ⅱ`로 자동 진행을 일시정지합니다.
- `▶`로 AI 액션을 한 단계만 진행합니다.
- `0.5×`~`4×`로 액션 사이 표시 시간을 바꿉니다.
- 상단 액션 배너와 오른쪽 타임라인에서 선택과 결과를 순서대로 확인합니다.

AI가 수를 오래 계산해도 현재 보드는 그대로 보이며, 계산이 끝난 뒤 해당 액션 하나만 적용됩니다.

## 사람 덱

대기실의 **덱빌더**를 누르면 1,267종의 로컬 카드 카탈로그에서 이름, 카드 ID, 기술로 검색할 수 있습니다.

- 검색 결과의 `＋`를 누르거나 카드를 오른쪽 덱 영역으로 드래그해 추가합니다.
- 덱 카드의 `−`/`＋`로 수량을 조절합니다.
- 덱 카드를 왼쪽 제거 영역으로 드래그하면 1장이 빠집니다.
- 미완성 덱도 이름을 붙여 저장하고 다음 실행에서 다시 불러올 수 있습니다.
- 정확히 60장인 저장 덱은 대전 설정에서 바로 선택할 수 있습니다.
- 기본 에너지를 제외한 같은 이름의 카드는 최대 4장으로 검사됩니다.

저장한 덱은 `app/user_data/decks.json`에 보관됩니다. CABT 폴더를 다른 곳으로 옮기거나 새 버전으로 교체할 때 이 파일을 함께 복사하면 덱을 유지할 수 있습니다.

## 기록 저장

- 게임 종료 후 `기록 ZIP` 버튼으로 전체 기록을 내려받을 수 있습니다.
- `공식 JSON` 버튼은 Kaggle 에피소드와 같은 최상위 구조의 JSON만 별도로 내려받습니다.
- 기록 ZIP에는 `metadata.json`, `transitions.jsonl`, 양쪽 덱, `replay_visualize.json`, `official_replay.json`이 포함됩니다.
- `official_replay.json`은 `configuration`, `info`, `steps`, `rewards`, `statuses`, `specification`을 포함하며 양쪽 덱 제출 단계와 이후 선택 액션을 기록합니다.
- 로컬 대전이므로 `EpisodeId`와 UUID는 로컬에서 생성됩니다. Kaggle 서버의 실제 경기 번호나 서명을 위조하지 않습니다.
- 로컬 기록은 `app/records/` 아래에도 저장됩니다.
- 저장한 ZIP, `official_replay.json`, `replay_visualize.json`은 이 프로그램의 **리플레이 불러오기**로 다시 열 수 있습니다.

## LAN 실행

다른 Windows PC의 브라우저에서 접속해야 할 때만 `RUN_CABT_LAN.bat`을 사용합니다. Windows 방화벽에서 개인 네트워크 접근을 허용한 뒤, 같은 네트워크의 다른 PC에서 `http://서버PC의 IPv4주소:8765`로 접속합니다.

## 문제 해결

- 첫 실행 실패: 인터넷 연결과 회사·학교 네트워크의 Python/PyPI 다운로드 차단 여부를 확인한 뒤 다시 실행합니다.
- 포트 충돌: 이미 실행 중인 CABT 창을 닫고 다시 실행합니다.
- 리플레이 오류: CABT 기록 ZIP 또는 유효한 `replay_visualize.json`/`transitions.jsonl`인지 확인합니다.
- 너무 큰 리플레이: 업로드 한도는 128MB이며 최대 5,000프레임까지 읽습니다.
- AI 로드 실패: 오류 메시지에서 누락 모듈, 잘못된 `deck.csv`, `agent()` 진입점 여부를 확인합니다.
- 카드 이미지 미표시: 대기실에서 `다시 검색`을 누릅니다.
- 저장 덱이 보이지 않음: 기존 CABT의 `app/user_data/decks.json`을 새 CABT의 같은 위치로 복사합니다.

지원 환경은 64비트 Windows 10/11입니다.

## 온라인 플레이어 매칭

공개 모드에서는 위에서 선택한 60장 덱과 플레이어 이름으로 다른 사용자와 대전할 수 있습니다.

- **빠른 매칭:** 같은 서버에서 기다리는 사용자와 자동 연결
- **친구 방:** 6자리 방 코드를 만들고 상대가 코드로 참가
- **서버 권한형 진행:** 현재 차례와 선택 가능한 option index를 서버가 검증
- **비공개 정보 보호:** 자기 패만 전송하며 상대 패는 브라우저에 보내지 않음
- **게임별 격리:** 대전마다 별도의 CABT 네이티브 워커 프로세스 사용
- **재접속:** 같은 브라우저 쿠키가 남아 있으면 진행 중 게임으로 복귀
- **이탈 표시:** 상대가 나가거나 연결 확인이 끊기면 화면에 상태 표시
- **기록 저장:** PvP 기록 ZIP, 공식 JSON, 공식 뷰어 파일 다운로드

현재 매칭 대기열과 진행 중 게임은 단일 서버 메모리에 유지됩니다. 따라서 배포 인스턴스는 정확히 1개를 사용해야 하며, 배포·재시작 시 진행 중인 대전은 종료됩니다. 저장 완료된 기록은 `/data` Volume에 남습니다.

## 웹 공개 배포와 결과 수집

이 버전에는 공개 웹 서버용 AI 다중 세션과 플레이어 온라인 매칭이 포함되어 있습니다. 각 AI 게임과 PvP 게임은 별도 CABT 엔진 프로세스를 사용하므로 다른 사용자의 상태와 섞이지 않습니다.

기본 권장 구성은 **Fly.io 도쿄 리전 단일 Machine + `/data` Volume**입니다. 고정 월 비용과 서버 제어권이 더 중요하면 **일반 VPS + Docker Compose + Caddy** 구성을 사용하세요.

- Fly.io: [`DEPLOY_FLYIO.md`](DEPLOY_FLYIO.md)
- 일반 VPS: [`DEPLOY_VPS.md`](DEPLOY_VPS.md)
- Railway 대안 절차: [`DEPLOY_RAILWAY.md`](DEPLOY_RAILWAY.md)

공개 모드에서 제공되는 기능:

- 빠른 매칭과 6자리 친구 방
- 브라우저 사용자별 독립 AI 대전 세션
- 게임 종료 후 사용자 동의 기반 AI 대전 결과 전송
- `/admin` 관리자 화면에서 결과 목록 확인 및 기록 ZIP 다운로드
- `/data/records`, `/data/submissions` 영구 저장
- 세션 유휴 자동 종료, 동시 게임 수 및 매칭 대기자 수 제한

공개 서버에서는 보안을 위해 사용자의 임의 AI ZIP 업로드, 공용 덱 저장·삭제, 카드 이미지 재검색이 자동 차단됩니다. 서버에 제공할 AI는 배포 전에 `app/agents/`에 넣으세요.

Windows PC에서 공개 모드를 시험하려면 `RUN_CABT_PUBLIC.bat`을 실행합니다. 기본 관리자 토큰은 예제 값이므로 인터넷에 공개하기 전에 반드시 변경해야 합니다.

## 전투 화면 가독성 개선

- 프라이즈는 남은 수량 숫자와 6장의 카드 표시를 함께 보여 줍니다.
- 각 포켓몬 아래에 부착 에너지 카드 이미지, 에너지 종류별 개수, 도구가 별도 패널로 표시됩니다.
- 트래시는 최신 카드 이미지와 전체 장수를 항상 표시하며, 펼치면 전체 트래시 카드를 볼 수 있습니다.
- 좁은 화면에서는 자원 패널과 카드 영역이 자동으로 재배치됩니다.
